# Incidents

Record real project failures here when they affect correctness, reliability, privacy or release confidence.

An incident record should include:

- date/time
- app version
- git commit
- device / Android version
- pre-failure state
- technical error
- sanitized stack trace/log excerpt
- retry/offset/status where relevant
- reproduction status
- containment
- root cause
- regression test status
- fix/verification references

Never include media content, GPS, passwords, tokens, cloud credentials or unnecessary PII.
