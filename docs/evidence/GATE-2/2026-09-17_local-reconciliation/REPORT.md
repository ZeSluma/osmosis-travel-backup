## Implementation and limits

Room schema3 adds `local_candidates` and replica `localPresence`, with additive2→3 and chained1→2→3 migrations. Preserve unknowns, old localLocator/partial bytes, recording/capture/path data and no-backup/private storage. No destructive fallback, new dependency, Gradle/configuration change or protocol/downloader rewrite.

`LocalMediaInventory` queries only accessible MediaStore metadata below exact Movies/Osmosis/, Pictures/Osmosis/ and Download/Osmosis/ roots on primary phone storage. The query includes pending entries so incomplete files are not mistaken for completed candidates; null/provider/permission failures and unstable/version-changing/over-limit inventories are UNAVAILABLE, never empty-success. Scan cap20000 entries. Scope is accessible MediaStore rows, not a claim of exhaustive access to all phone storage. Read-only descriptors are opened solely for `fstat` (actual length, inode/device/change times), then closed; zero payload bytes are read. No file stream, content hash, raw path crawl or metadata/GPS extraction from payloads. Missing/inaccessible/nonregular descriptors yield UNAVAILABLE rather than asserting absence. Pending/trash/accessibility and provider-index staleness remain observation limits; candidate metadata is not actual-byte integrity proof.

Association requires the configured landing-zone scope plus exact original name or reserved path, exact positive known size and published state. Conflicts (including same-name/wrong-size/pending), multiple candidates, cross-asset claims, changed provider version/generation/metadata and missing prior references retain explicit uncertainty. Same-size/different-name alone never creates a relationship. MediaStore version/generation/date-added/date-modified evidence is persisted as an opaque change token, never treated as source equality. Prior unresolved changed evidence stays unresolved; previous references remain as MISSING/UNAVAILABLE rather than being erased.

Candidate rows persist URI/name/directory/size/pending/version token, association rule, METADATA_ONLY_NOT_SOURCE_PROOF confidence, status, observation time and source-owner epoch. They remain app-private/no-backup; diagnostics export counts/enums/hashed identities only. Unique plausible associations use `LOCAL_PRESENT_UNVERIFIED`, keep committed transfer bytes unchanged and preserve the reserved capture-day/path separately from the existing physical URI. No relocation, rename, deletion or VERIFIED promotion. Ambiguous/conflicted/missing/inaccessible associations use NEEDS_REVALIDATION; known transfer PARTIAL/TRANSFERRED_UNVERIFIED progress is not overwritten by a metadata observation.

Fenced transactional local reconciliation runs after source ingestion on the existing serialized coordinator worker. It chooses no arbitrary first candidate and retains references across restart. Plans distinguish accessible absence (DOWNLOAD), local unverified candidate (VERIFY_EXISTING), and ambiguity/change/missing/access failure (REVALIDATE_IDENTITY). Only an independently current verified proof may justify skip; contradictory local evidence overrides stale proof. This gate still executes no new transfer engine. G3 must resolve candidate/source equivalence and decide safe reuse/retransmission; a candidate is neither permanent skip authority nor permission to overwrite/re-download automatically.

Official API references reviewed: [MediaStore](https://developer.android.com/reference/android/provider/MediaStore) documents pending query behavior, database versions and generation counters; [shared media access](https://developer.android.com/training/data-storage/shared/media) describes scoped access. Generation/version observations are change evidence only. API29 uses the supported pending URI; API30+ uses query extras and generation metadata. No newly requested storage permission.
