# Credentials, camera boundary and Android execution

Read-only source at the REPORT commit; paths below are under `app/src/main/java/dev/konraditurbe/osmosis/`. Targets are design requirements, not installed controls.

## Credential inventory and threat model

| Current item | Persistence / exposure / camera scope |
|---|---|
| Camera Wi-Fi passphrase | `ui/MainActivity.kt:760,791,1915`: `osmosis` MODE_PRIVATE SharedPreferences key `pass_<Bluetooth address>`, plaintext string. Logical path `/data/user/0/dev.konraditurbe.osmosis/shared_prefs/osmosis.xml`; actual device file not accessed. Already per-camera lookup, address stability not a strong identity guarantee. BLE retrieval/manual entry; heap copies include offload password and ApJoiner retry state. |

| R-SDK identity and verification data | `rsdk/RsdkController.kt`: persisted `rsdk_device_id` and generated `rsdk_mac` in same prefs, per-install protocol identity (not necessarily phone hardware MAC). Short verification value is session material. Raw response logging needs sanitization. |
| Download mapping | `osmosis_downloads` stores URI/source associations, private operational metadata, not passwords. |
| Cloud/signing | No implemented OneDrive token store. CI keystore/password secrets are build-system credentials, never camera/ledger data; their existence or values in the fork were not inspected. |

Current allowBackup=false disables cloud Auto Backup but is not proof against every OEM device-to-device transfer. No explicit fullBackupContent/dataExtractionRules observed. Android app isolation/OS disk encryption does not turn preference strings into app-encrypted secrets. [Android backup guidance](https://developer.android.com/identity/data/autobackup) documents the D2D caveat and exclusions.

CURRENT_CREDENTIAL_STORAGE: plaintext app-private per-camera preferences plus transient heap/protocol data. TARGET_CREDENTIAL_STORAGE: platform Keystore AES-GCM wrapping per-camera ciphertext blobs in app-private no-backup storage; fresh nonces, versioned format and immutable camera-record ID as authenticated context; ledger stores only opaque references. MIGRATION_REQUIRED: yes. OPEN_RISKS: live-process/root compromise, protocol peer trust, identifier changes, key invalidation and OEM transfer behavior.

The non-exportable key mitigates off-device copying of credential files without that key. Hardware backing is a checked capability, not assumed. It does not hide plaintext while used, sanitize logs, secure HTTP or protect public Movies files. Ordinary authorized background backup must not require a biometric prompt per read; keystore access after device unlock and actual screen-off behavior require tests. Do not promise reliable zeroing of JVM Strings. [Keystore basis](https://developer.android.com/privacy-and-security/keystore).

Migration: read legacy value inside app only; bind to reviewed camera identity; write versioned authenticated ciphertext and durable migration marker; decrypt/compare in memory; durably mark success before removing plaintext. Crash recovery repeats idempotently, retaining legacy value until success, never logging it. Per-camera reset removes only that camera's secret after intentional user action. Invalidated key/decrypt failure/restore -> CREDENTIAL_UNAVAILABLE and normal re-pair/re-entry; no automatic camera reset and no fabricated wrong-password claim. Explicitly exclude blobs, legacy prefs, DB/WAL/journals and pairing identifiers in both legacy/new backup and D2D rules; use noBackup storage where supported. Reinstallation cannot silently restore authorization. Tests SC01/SC02 must verify these controls, not only manifest strings.

## Cleartext boundary

CURRENT_CLEARTEXT_SCOPE: global true in `res/xml/network_security_config.xml`. `net/HttpClient.kt` defaults to `192.168.2.1`; MainActivity uses that literal for listing and preview. Camera HTTP uses port80, `/v2` and model-specific `/v1` media APIs. Current `URL.openConnection` relies on global routing; no explicit redirect denial. DumlTransport's peer address derives from the supplied host; it is not negotiated HTTP endpoint discovery. The reviewed Pocket baseline worked with that profile, not proof all supported cameras always have the same address.

TARGET_CLEARTEXT_SCOPE: deny by default; a finite model-profile exception for exact `192.168.2.1`, includeSubdomains=false, alongside mandatory transport enforcement. XML_SCOPING_FEASIBLE: **yes for exact literal host matching, insufficient for the complete boundary**. This is a source-backed inference: AOSP [XmlConfigSource.parseDomain](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/security/net/config/XmlConfigSource.java) accepts the trimmed domain string; [ApplicationConfig.getConfigForHostname](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/security/net/config/ApplicationConfig.java) matches exact strings. It is not an executed Android-client compatibility test. [Platform configuration](https://developer.android.com/privacy-and-security/security-config) does not express Network identity, interface, port, CIDR or a runtime-negotiated address.

COMPENSATING_CONTROLS: validated paired-session camera profile plus owned Network/epoch; exact host/port80/protocol allowlist; reject redirects (including same-IP redirection to unapproved paths), URL user-info and arbitrary supplied URLs; normalize/bound paths and responses; network-specific DNS if a supported profile later needs it. Unknown addresses fail closed pending explicit profile review; no silent global-allow fallback. Include thumbnails, HEAD/range downloads, preview/MediaExtractor and TCP/UDP control paths in the audit. Low-level sockets/native clients must be guarded even if they do not honor XML. Cloud/OAuth uses a separate HTTPS-only client, no camera credentials/routing context and no cleartext redirect. An IP exception alone could otherwise also allow that IP on another network. BLOCKER_STATUS: design resolved, enforcement deferred SC03/N tests; broad existing config remains disclosed debt. Local HTTP still lacks cryptographic server/content authentication; routing is not integrity proof.

## Network ownership

`SyncCoordinator -> CameraConnectionManager (the CameraConnectionController in ADR0004) -> callback/current Android Network + epoch -> bound HTTP/TCP/UDP adapters`. These names denote one owner, not two controllers. UI observes state and handles consent only. Owner lifetime is service/coordinator, not MainActivity. BLE GATT callbacks likewise use application context and structured lifetime; no Android API requires Activity ownership of the connection itself.

[WifiNetworkSpecifier](https://developer.android.com/develop/connectivity/wifi/wifi-bootstrap) supplies a local request whose callback receives Network; callback registration must remain alive and be unregistered on release. Availability does not establish Internet or camera protocol READY. Approval may recur. Persist intent/association, never reuse a netId after process death. `onLost` fences only its epoch, cancels sockets, retains partial truth, then bounded reconnect with fresh handshake and identity checks.

[Network APIs](https://developer.android.com/reference/android/net/Network) provide `openConnection`, socketFactory, network DNS and bindSocket for an unconnected DatagramSocket. Therefore PROCESS_WIDE_BINDING_REQUIRED: no in the complete target design; currently yes for unchanged routing. PER_NETWORK_TRANSPORT_FEASIBLE: API-backed, actual adapter behavior NOT_TESTED. Remove bindProcessToNetwork only after all routes including preview/native consumers are adapted or provided scoped streams. CLOUD_COEXISTENCE_MODEL: sequential camera-local verification, release camera request, then Internet replication by default. UNPROVEN_ASSUMPTIONS: OEM concurrent networks, wake/consent behavior, HTTP/native enforcement, Pocket identity and liveness; N01-N05/G7. No cloud prerequisite for local success.

## Execution contract for min29 / target36

EXECUTION_MODEL: one non-exported connectedDevice FGS hosts one fenced SyncCoordinator for an intentional external-camera session. WHY_CONNECTED_DEVICE: Bluetooth/network peripheral interaction and sustained multi-GB local transfer; not Android's camera type, which concerns the phone camera. No transfer-size limit is inferred and no guaranteed survival is claimed.

Declare FOREGROUND_SERVICE and FOREGROUND_SERVICE_CONNECTED_DEVICE, type connectedDevice, and pass that type when promoting service. Satisfy a listed network/Bluetooth prerequisite and independently obtain actual Bluetooth/Nearby Wi-Fi permissions. Current baseline has only location-typed GpsService; backup FGS is not implemented. [FGS types](https://developer.android.com/develop/background-work/services/fgs/service-types).

Start from visible user action after consent; call startForegroundService then promptly promote with a valid notification/channel and explicit immutable Pause/Open actions. Android13+ POST_NOTIFICATIONS governs notification visibility, not permission to launch an otherwise eligible FGS; denial still needs compliant foreground notification/Task Manager disclosure and honest UX. [Launch contract](https://developer.android.com/develop/background-work/services/fgs/launch), [notification permission](https://developer.android.com/develop/ui/views/notifications/notification-permission). Background restarts remain restricted; approval-required recovery emits USER_ACTION_REQUIRED instead of bypassing system UI. [Start restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start).

Memory owns Network/GATT/sockets, IO scopes and current lease. Only persisted intent, identities, generation/lease fencing, stable path/URI, byte checkpoint, retry budget and verification evidence survive. On permitted restart acquire a new fence, reconcile actual file/MediaStore/source, then resume safe work; old callbacks cannot complete it. No automatic restart timing guarantee, no Network resurrection, no completion based on callbacks alone. Force-stop/user stop is respected; reopen reconciles instead of resurrecting stopped work. Task Manager termination may omit callbacks. [User stopping](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping).

Background Activity detachment does not cancel target service work. FGS alone does not keep CPU awake; evaluate a narrowly timed partial wake lock only with measured need, release at every stop/error and avoid long idle retry holds. Screen-off/battery/thermal/process-loss behavior stays G7 NOT_TESTED. [Power guidance](https://developer.android.com/develop/background-work/background-tasks/awake).

WORKMANAGER_ROLE: optional bounded deferred reconciliation/secondary replication; not live camera-session ownership and no quota bypass. UIDT_ROLE: optional later user-started cloud transfer or alternative if measured FGS limitations demand it; unnecessary for the initial coherent device-session owner. See [transfer API guidance](https://developer.android.com/develop/background-work/background-tasks/data-transfer-options) and ADR0003. REMAINING_HARDWARE_PROOF: SC04/X/N matrix on S25/Pocket; no hardware resumed.

## Target37 migration

Current target36 stays unchanged. Direct Pocket TCP/UDP/HTTP does not use an NSD picker; plan ACCESS_LOCAL_NETWORK declaration/runtime grant when migrating to37, before local IO. Permission denial/revocation is distinct from bad credentials and preserves partials. Nearby-group prior grants may affect prompts, so query permission rather than assume a fresh dialog. BLE and Wi-Fi association permissions remain separate responsibilities. [Official local-network guidance](https://developer.android.com/privacy-and-security/local-network-permission).

SC07/N05: on separately authorized Android16 device test RESTRICT_LOCAL_NETWORK compatibility opt-in, required reboot, denied/granted Nearby permission and restore settings; do not flash the current phone. On Android17 target37 test fresh install, upgrade, prior Nearby grant, denial/revoke during TCP/UDP/range IO and recovery. Persist sanitized reason codes; no SDK bump until this migration task is authorized.
