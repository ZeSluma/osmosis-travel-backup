# ADR0013 — Orthogonal integrity evidence and strict overall verification

2026-09-17. Explicit user decision supersedes G3 entry-review alternatives. Transfer/file integrity and source identity/equivalence are independent evidence dimensions. CONFIRMED transfer integrity plus UNCONFIRMED source identity always yields overall UNVERIFIED. No weaker lifecycle/UI state named verified is introduced. VERIFIED requires the full integrity/source contract and current readable/published local binding. Neither transfer evidence alone nor local checksum proves camera equality.

Positive transfer evidence is append-only and bound to exact asset, private locator, local revision, expected length, method revision and measured receipt. Source uncertainty never erases it. Reuse requires the same independently measured local binding; a changed revision/locator/length, contradictory failed receipt or unreadability blocks current reuse without deleting history. Source equivalence is a separate explicit proof linked to the transfer receipt, proven source version and owner epoch. A new source epoch invalidates current source authority while retaining file evidence. No current Pocket adapter supplies immutable-version proof.

Schema5-to-6 is additive: transfer_integrity, source_equivalence and transfer_attempts; old rows generate no evidence and no VERIFIED promotion. Pure overall/completeness predicates require both dimensions; publication is an additional independent necessary condition. G9 deletion remains unimplemented and unauthorized; no evidence recording API can authorize it. Required recording members, inventory coverage and independent replica domains remain mandatory beyond per-file overall verification.

Validation must include all dimension combinations, missing source proof, migration/restart, changed bindings, stale writer rejection, epoch changes, publication pending and preservation of positive evidence. HTTP validator uses exact64-bit full/tail length and200/206/Content-Range checks, rejects200 append/416/encoding/overflow/inconsistent lengths. A resumed concatenation also needs prefix integrity and source continuity. EOF alone cannot establish confirmed integrity; successful flush/close/readback are required.

The scoped Pocket4Pro full-video UI now uses the strict engine and explicit camera Network, new-owned MediaStore pending allocation, durable attempt journal and independent readback evidence. It has no legacy fallback, overwrite/adoption by filename, automatic retry or verification promotion. Existing unverified copies remain reviewable without retransfer. Missing prefix/source-continuity proof blocks partial retry; successful production resume remains unproven. Other camera legacy paths are unchanged and gain no integrity authority. Software/emulator results are scoped separately from target evidence. Real media read/hash/download/delete remains unauthorized.
