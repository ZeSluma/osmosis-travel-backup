# ADR0009 — GATE-2 foundation and continuous execution

2026-09-17. Current explicit user instructions authorize GATE-2 and supersede earlier per-gate authorization stops through the global continuous policy persisted in AGENTS.md. Dependencies, genuine human decisions, physical hardware, invariants, main/merge/release and destructive-operation boundaries remain binding. Historical G1 evidence is unchanged.

Room2.8.5/KSP2.3.12 (reviewed in G2 evidence) implement typed persistence. Schema1 is the exported initial foundation; additive migration1→2 introduces nullable local locator without inventing completion. No destructive fallback; corruption is preserved and blocks operation. DB/WAL/journal live under noBackupFilesDir. Explicit cloud/D2D/legacy exclusions additionally cover private operational metadata and existing preferences. Credentials are never ledger columns.

Source association is hashed privately; this is not cryptographic identity proof. Candidate fingerprints include source/storage/path/size/time/type/handle/version evidence. Current Pocket adapter has no proven immutable version or capture-time/zone contract: identity remains ambiguous, filename time untrusted, capture-day falls back explicitly. These are visible limitations, not permission to skip or report VERIFIED. Strong identity in synthetic tests is a fake capability, not a claim about Pocket.

Transactional repository owns transitions. Each new request increments durable source ownerEpoch; stale callbacks cannot mutate. Duplicate request IDs are idempotent. Single process coordinator serializes normal writes. Remote absence never deletes ledger/history/local bytes. Private recording links require explicit enumerator evidence; absent required members and unresolved relationships block completeness. Capture/path reservations persist before future IO; changed clocks do not silently relocate them.

Read-only pagination is separate from UI and bounded against stalled/unstable cursors. Current protocol listing does not prove all stores/sidecars or stable generation; real snapshots remain INCOMPLETE. G2 automatically computes deterministic plans but executes no new transfer engine. No LOCAL_VERIFIED promotion is implemented; successful transfers may only be TRANSFERRED_UNVERIFIED pending G3 evidence. Phone/SSD/cloud share future relative-path semantics; no replica IO introduced.

G2 physical evidence remains NOT_TESTED during the user pause. The isolated emulator is synthetic software verification, never target hardware proof. Scope does not claim G7 background/reconnect reliability or G4 complete one-open backup.
## SC01/SC02 implementation

The core test plan assigned credential migration to G2. CameraCredentialStore now isolates per-camera AES-GCM blobs in noBackupFilesDir with Android Keystore keys and authenticated camera context. The selected camera's legacy preference is retired only after an atomic durable ciphertext write and successful decrypt/compare. Interrupted migration retries idempotently; corruption, conflict or unavailable key returns unavailable without falling back to a different camera, resetting the camera or logging values. User re-entry can recover a missing key. Permanent Keystore provider errors remain an honest storage failure, not silent plaintext fallback.

Existing MainActivity credential reads/writes route through a serialized background worker and transient per-Activity cache. Camera-selection request generations reject late replies; the prompt reports failed secure persistence. Existing explicit Forget camera action remains the only credential-removal UI. This does not authorize a tool to inspect real credentials; tests use separate synthetic preferences/keys/files. No new cryptographic dependency, exported component or secret ledger column. Room contributes one non-exported internal invalidation service; see the merged-manifest audit.

Synthetic emulator tests interrupt before/after write, after decrypt verification and after plaintext retirement; reopen and verify recovery, per-camera isolation, fresh nonce/ciphertext, authenticated rejection of swapped/tampered blobs, missing-key re-entry and scoped synthetic forget. Actual S25 Keystore/OEM transfer behavior remains HIL NOT_TESTED. JVM String erasure and hardware-backed keys are not claimed. Official references: https://developer.android.com/privacy-and-security/keystore and https://developer.android.com/identity/data/autobackup .
